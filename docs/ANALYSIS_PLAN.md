## 0. 計画を変えた理由（群の比較 → 順位相関）

10/08 の合意は「低ランク群（アイアン1〜シルバー3）と高ランク群（アセンダント1以上）を各10名で比べる」だった。
2026-11-09 時点の応募者は5名で、集まっても合計10名程度の見込み。しかもゴールド〜ダイヤモンド（`mid`）はどちらの群にも入らない。

並べ替え検定では、**どんなに差がはっきりしていても p 値はある値より小さくならない**（各群の人数だけで決まる。一方の群の全員が他方の全員より大きいときが下限）：

| 各群の人数 | p 値の下限（両側） |
|---|---|
| 3 vs 3 | 0.100 |
| 4 vs 4 | 0.029 |
| 5 vs 5 | 0.008 |

主要比較を6つにして Holm で補正すると、一番厳しい基準は 0.05 ÷ 6 ≒ 0.0083。各群4名以下では、**データを見る前から「有意差なし」が確定する**。
そこで、`mid` を含む全員を使い、ランクを順位として Gaze % との順位相関を調べる（案Y）。

- 変えた理由は**人数の見込み**であり、結果ではない（本実験のデータは未取得、予備実験は群の比較をしていない）
- 題目「熟練度の**関係**」とも一致する
- 群の比較（low / high）は記述的な結果として残す（§7）
- 倫理審査の書類に分析方法（群の比較）を書いていた場合は、変更の届けが要るか教授に確認する

## 1. 対象者と除外

- 対象：本実験（アンレート）の参加者全員。**`mid` も含める**。未ランク者は除外（10/08 の合意どおり、ランクの値が無いため）
- 除外は `aggregate_sessions.py` の `qc_report.csv` で**機械的に**決める（その場の判断で足したり減らしたりしない）。基準は CLAUDE.md §2 の「除外基準」：
  - 区間内の有効率 ≥ 0.7
  - 同期が confirmed_based かつ期待範囲内
  - 較正が合格（不合格の人は感度分析でのみ使う）
  - 解像度が一致
  - 実測の眼−画面距離と基準 650 mm の差 ≤ 100 mm
  - **区間の coverage ≥ 0.9**（2026-11-09 決定）
  - **分析時間の下限は設けない**（2026-11-09 決定。§1a）
- **除外はセッション（試合）単位**（2026-11-10 決定）。上の基準はセッションごとに判定し、除外候補（`qc_report.csv` の `exclude_candidate`）のセッションを抜いてから参加者単位でサンプル数・時間を足す（`participant_aoi_metrics.csv` の `session_set: excluding_flagged`。`aggregate_sessions.py` の既存の動作）
  - 2試合した人（降参）は、残ったセッションだけで主解析に入れる。分析時間の下限は設けないので、1試合分だけ残った人も含める
  - すべてのセッションが除外候補になった人は、主解析から外れる
  - 理由：基準（同期・較正・有効率など）はどれもセッションの記録の品質を見ている。1試合の記録の不具合で、問題のない別の試合まで捨てる理由がない
  - 明文化のきっかけ：S01（11/10）の1試合目が同期の期待範囲外（confirmed 45.0 ms、LAB_CHECKLIST 4b）。コードの動作は以前からセッション単位で、それを計画に書いただけ（S01 の集計結果を見る前）
- 除外の理由と人数を、応募 → 参加 → 除外 → 解析の流れの図にして報告する。**参加者の数とセッションの数の両方**を書く（2試合した人のうち1試合だけ除外した人がいるため）
- 予備実験の参加者（PL01〜PL03、実験者本人）は本解析に入れない

### 1a. 分析時間の下限を設けない理由
- 人数が少なく、1人除外するごとの損失が大きい
- 分析時間の短い人を外すと、早く死ぬ人（＝ランクと関係しうる）を選んで外すことになり、偏りが入りうる
- アンレートは最短でも13ラウンドあり、降参で終わったときはもう1試合する（11/05 決定）ので、極端に短いデータは出にくい
- その代わり、**参加者ごとの分析時間（秒）を結果の表に必ず載せる**。分析時間が短い人の値は、小さい AOI ほど偶然の影響を受けやすいことを限界に書く

## 4. 主検定：ランクとの順位相関（案Y）

### 4a. ランクを数にする
- 使うのは **`rank_current`**（台帳。11/06 の group との照合と同じ）。`rank_peak` を使った場合は感度分析（§6）
- 段位とディビジョンから順番の数を作る：アイアン1 = 1、アイアン2 = 2、…、イモータル3 = 24、レディアント = 25
  - 例：シルバー2 = 8、ゴールド1 = 10、アセンダント1 = 19
- 順位相関は**順番しか使わない**ので、「アイアンとブロンズの差」と「ダイヤとアセンダントの差」が同じ幅かどうかは結果に影響しない
- 同じランクの人がいたら、同順位（平均順位）として扱う

### 4b. 検定
- **Spearman の順位相関係数 ρ**（ランクの数と、AOI 別 Gaze % の順位の相関）
- **両側**（ランクが高いほど多く見るか少なく見るか、方向は AOI ごとに予想しにくいため）
- **並べ替え検定**（2026-11-09 決定）：Gaze % の値を参加者の間でランダムに入れ替えて ρ を計算し直すことを **100,000 回**行い、
  実際の |ρ| 以上になった回数 k から p = (k + 1) / (100,000 + 1)。乱数のシードを固定して出力に記録する（同じ結果を再現できる）
  - 近似の式（t 分布）を使わない理由：少人数では近似がずれる
- 主要6つ・副次3つのそれぞれのファミリー内で **Holm 補正**

### 4c. 効果量
- p 値に関係なく、すべての比較で **ρ と 95% 信頼区間**を報告する
- 信頼区間：Fisher の z 変換に、Spearman 用の標準誤差 √((1 + ρ²/2)/(n − 3))（Bonett & Wright, 2000）を使う

### 4d. この人数で何が検出できるか（データを見る前の目安）
並べ替え検定で「有意」になるために必要な |ρ| の大きさ（同順位が無い場合のシミュレーション）：

| 人数 | 基準 0.05 | 主要比較で一番厳しい基準 0.0083 |
|---|---|---|
| 8 | 0.71 | 0.86 |
| 10 | 0.64 | 0.79 |
| 12 | 0.58 | 0.73 |

- **かなり強い関係でないと有意にならない**。「有意でない」は「関係がない」ではない。考察は ρ の大きさと信頼区間の幅を軸に書く
- 解析できる人数が **5名以下**だと、主要比較は p 値の下限（5名で 2/120 ≒ 0.017）が 0.0083 を上回り、有意になりえない。その場合も ρ と信頼区間は報告する
- 同じランクの人が多い、または全員が狭い範囲のランクに集まると、検出力はさらに下がる（ランクの範囲が狭いことを限界に書く）

### 4e. この方法の限界（方法・限界の章に書く）
- **単調な関係**（ランクが上がるほど一方向に増える・減る）しか検出できない。中位のランクだけが多く見る、のような山形の関係は検出できない → 一人ひとりの点の図（§7）で確認する
- 相関であって因果ではない。ランクは、プレイ時間・年齢・使うロールなどと一緒に動く
- ランクは act ごとに変わり、`rank_current` はその時点の値

## 5. 床効果と、検定が計算できないとき

- **案B（下部HUDの床効果）は採らない**（2026-11-09 決定）。PENDING_DECISIONS 1 の文案の基準（予備実験の全員が 0.5% 未満なら案B）を採用し、PL02 の下部HUDまとめが 1.53% で基準を満たさないため。下部HUDまとめは主要比較に残す
- 本実験で、ある AOI の値が**全員同じ**（例：全員 0）だと ρ が計算できない。そのときは：
  - その比較は検定せず、記述（中央値・範囲・1件でも見た人の数）だけを報告する
  - **Holm のファミリーの数は 6（副次は 3）のまま**にする（その比較の p = 1 として扱う）。データを見てからファミリーを小さくすると、補正が都合よく緩くなるため
- 0 の人が多くても、全員同じでなければ検定はする（同順位として扱う）。0 の人の数を併記する
