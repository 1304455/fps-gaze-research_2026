## 2. 較正の合格ライン — 何を決めるのか

### そもそも何をしているか
試合の前に9点で較正したあと、画面上の検証点（HUD の位置を含む）を見てもらい、「本当に見ている場所」と「Spark が出した視線の位置」が
何度ずれているか（accuracy）を測っている。**合格ライン**は「このずれまでなら、AOI の判定に使ってよい」という線。

いまのツールの既定（案）は2つ：
- 全点の平均ずれ **≤ 1.0°**
- HUD の各点のずれ **≤ 1.5°**（1点でも超えたら不合格）
- （SDK の較正そのものが失敗したら、ずれによらず不合格）

### 決める必要があること
1. **線の値**（1.0° / 1.5° のままか）
2. **不合格だったときの手順**（何回までやり直すか、それでもだめならどうするか）
3. **最後まで不合格だった人のデータの扱い**（除外するか）

### 線の値を考える材料
- AOI の大きさとの関係：ずれが AOI の短辺の半分を超えると、**AOI の中心を見ていても AOI の外と判定されうる**
  - crosshair：半径 2° → 1.5° のずれでも中心を見ていれば中に入る
  - 下部HUD：高さ 2.5〜2.8° → 半分は約 1.3°。**1.5° は下部HUDにとっては甘い**
- これまでの実測：標準姿勢（10/20）は平均 0.68°・HUD 最大 0.99° で、1.5° でも 1.3° でも合格。
  前のめり姿勢（約 585 mm）では HUD 点の最大が 1.5° を超えた（credits・minimap・enemy_team_status）
- 線を厳しくする（例：HUD 1.3°）→ 下部HUDの判定は信頼しやすくなるが、不合格の人が増え、除外で人数が減る（1群10名なので1人の重みが大きい）

### 決めないと何が困るか
- **その場の判断になる**：実験者が「少し超えたけどまあいいか」と人によって変えると、データの質が参加者ごとにばらつき、卒論の方法の章にも書けない
- **後から線を引くと疑われる**：データを見てから「この人を残せる線」を選ぶと、結果に都合よく除外したように見える
- **凍結に関わる**：合格ラインは計測側のコード（`calibrate_validate.py` の既定値）と手順書に入っている。凍結（11/6）の後に変えると計測側の変更になる。
  コマンドの引数で変えることもできるが、毎回打ち間違えないよう既定値で決めておくのが安全

> 2026-10-30 追記：10/29 に実験者以外（PL01）で較正＋検証が5回とも不合格だった（LAB_CHECKLIST 2c）。原因は人の注視の仕方（次の点を先読みする）と、回によって出る上段のずれの2つが疑われ、確認中。**この件が解けるまで、下の手順案（3回不合格で除外）は確定しない**。先に手順 A〜C で原因を確かめ、説明や `--settle-ms` を変えるならそのうえで合格ラインと回数を決める

### 不合格のときの手順 — 案

| 回 | やること |
|---|---|
| 1回目 不合格 | どの点が悪いかを見る（全体的に悪い／端の点だけ／有効率が低い）。有効率が低いなら眼鏡の反射・照明・前髪を確認。頭部位置ガイドで標準姿勢に戻して、**較正からやり直す** |
| 2回目 不合格 | 1〜2分休憩して目を休ませ、眼鏡・照明・椅子の高さをもう一度確認して3回目 |
| 3回目 不合格 | 較正はここで打ち切る。**試合（計測）は予定どおり行う**（参加者の時間を無駄にしない。データは保存する）。台帳の notes に `calib_fail=3` と書き、**主解析から除外**する（除外基準の「較正が合格」に当たる） |

- 回数の上限を3回にする理由：1回 3〜5 分なので、3回で最大 約 15 分。95 分の想定に収まる上限
  （ただし、試合が 50 分かかり較正が3回になると、説明・同意・試合後の検証を含めて 95 分ぎりぎり。アンレートの予備実験で所要時間を確かめる）
- **使うのは最後に行った較正**：SDK では最後の較正が有効になるので、前の回の方が良くてもその回に戻せない
- **例外を作らない**：「HUD の1点だけ少し超えた」でも不合格は不合格。その場の判断を入れないことが、この手順の目的
- 研究上の選択肢：3回目も不合格の人を「除外」ではなく「主解析には入れて、除いた場合を感度分析で示す」とする方法もある。
  人数が少ないので魅力はあるが、合格ラインを決める意味が薄れるので、推奨は除外

## 3. 多重比較の補正 — 何を決めるのか

### 何が問題か
検定は「本当は差が無いのに、偶然『差がある』と出てしまう」確率を 5%（有意水準 0.05）に抑える仕組み。
ところが**検定を何回もすると、どれか1つが偶然「差あり」と出る確率が増える**。

| 検定の数 | どれか1つが偶然「差あり」になる確率 |
|---|---|
| 1 | 5% |
| 3（主要比較：ミニマップ・クロスヘア・下部HUDまとめ） | 約 14% |
| 4（上部HUDも主要比較に入れた場合） | 約 19% |
| 6（主要3＋副次3） | 約 26% |

くじを3回引けば、1回引くより当たりやすいのと同じ。補正は「何回も検定したぶん、1回ごとの基準を厳しくする」こと。

### 決める必要があること
1. **どの検定をひとまとまり（ファミリー）として扱うか**：推奨は「主要比較で1つ」「副次比較で1つ」の2つに分ける
2. **補正の方法**
   - **補正なし**：見逃しは少ないが、偶然の「差あり」が増える。主要比較では勧めない
   - **Bonferroni**：基準を検定の数で割る（3つなら 0.05 ÷ 3 ≒ 0.0167）。単純だが厳しい
   - **Holm（推奨）**：p 値を小さい順に並べ、1番目は 0.05÷3、2番目は 0.05÷2、3番目は 0.05 と比べていき、どこかで届かなければそこで止める。
     偶然の「差あり」を抑える力は Bonferroni と同じで、見逃しは必ず同じか少ない
     - 例：p = 0.010, 0.030, 0.040 → 0.010 < 0.0167 ○、0.030 < 0.025 ×（ここで止める）→ 1番目だけ有意
3. **副次比較をどう扱うか**：主要比較とは別のファミリーとして Holm をかけるか、補正せず「探索的な結果」として報告するか（**どちらにするかを先に書いておく**）

### 決めないと何が困るか
- **結果を見てから選ぶと、選び方自体が結果をゆがめる**：p 値を見てから「補正しないと有意にならないから補正なしで」とすると、5% の約束が守られない。審査で必ず聞かれる
- **上部HUDを主要比較に入れるかで、検定の数（＝補正の強さ）が変わる**：だから上部HUDの扱い（予備実験の後に決める）を先に決め、その後で補正を決める順番になる
- **1群10名だと、もともと差を検出する力が弱い**：補正するとさらに弱くなる。だからこそ、p 値だけでなく効果量（3-4 の p̂）とその信頼区間を、有意かどうかに関係なく報告すると決めておくのが大事

### 推奨（案）
- 主要比較（3つ、または上部HUDを入れて4つ）に **Holm**
- 副次比較（HP・アビリティ・弾数）は別のファミリーとして **Holm**
- すべての比較で、効果量 p̂ と 95% 信頼区間を報告する

### 3-4. Brunner–Munzel 検定について一緒に決めておくこと
- **何を比べるか**：参加者ごとの値（1人1試合なので、その試合の AOI 別 Gaze %）を、低ランク群と高ランク群で比べる
- **効果量 p̂**：「低ランク群から1人、高ランク群から1人選んだとき、低ランク群の値の方が大きい確率」（同じ値なら半分と数える）。0.5 なら差なし
- **計算方法**：Brunner–Munzel には、t 分布で近似する方法と、並べ替え（permutation）で計算する方法がある。
  1群10名前後、しかも除外で減る可能性があるので、**並べ替え版**の方が安全（少人数で近似がずれにくい）。どちらにするか決める
- **全員が同じ値のとき**：両群とも全員 0 件など、どちらの群の中にもばらつきが無いと検定の値が計算できない。そのときは記述統計だけを報告する（1 の「本実験での安全策」）
