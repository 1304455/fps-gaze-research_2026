## T0 リポジトリ整備（P0）

**なぜ**：公開リポジトリの README に OBS WebSocket パスワードが平文で載っている。依存関係と設定ファイルに実態とのズレがある。

**やること**
1. README からパスワードを含むコマンド例を削除し、`--obs-config <gitignore済みのjson>` を使う例に置き換える。git履歴に残るので、**ユーザーに OBS 側のパスワード変更を依頼する**（削除だけでは不十分）。研究ノート由来の制御 token も同様に固定値を書かない
2. `.gitignore` に `obs_config*.json`（またはローカル設定ファイル名）を追加
3. `requirements.txt` を実態に合わせる：`keyboard` を削除（Vanguard上で使用禁止）、`pandas` / `obsws-python` / `PyQt5` を追加、`pywin32` は `; sys_platform == "win32"` マーカー付き。開発用に `requirements-dev.txt`（`pytest`）を分ける
4. `valorant_hud_aoi_circular.json` の `screen_name` を実態（3840x2160）に修正
5. `tobii_capture_with_sync_flash_v4.py` の import フォールバック `from gaze_estimation import obs_controller_v2` は実ファイル位置（`src/obs_controller_v2.py`）と合っていない。実害の有無を確認し、直すなら最小変更で
6. `aoi_analysis-ver3.py` がローカルにあればコミット（無ければ T4 で作る）

**受け入れ基準**：リポジトリ内に秘密情報の平文がない。クリーンな venv で `pip install -r requirements.txt` が通る（Windows）。

## T1 眼位置・瞳孔の記録追加とセッション台帳（P0）

**なぜ**
- 視角ベースの AOI（クロスヘア2°）や I-DT の分散閾値（1°）は眼−画面距離がないと正規化座標に換算できない。現在は距離を記録していない
- 実際の運用では `--skip-conditions-prompt` を使っており、マップ・エージェント・攻守などの条件がどこにも残っていない。ファイル名も `gaze_NA_1_default_...` になっている

**やること**
1. 視線CSVの `FIELDNAMES` の **末尾に** 次の列を追加（既存列は変えない）
   - `left_gaze_origin_z_mm`, `right_gaze_origin_z_mm`（`*_gaze_origin_in_user_coordinate_system` の z）, `left_gaze_origin_validity`, `right_gaze_origin_validity`
   - `left_pupil_diameter_mm`, `right_pupil_diameter_mm`, `left_pupil_validity`, `right_pupil_validity`
   - 欠測は既存と同じく `"NaN"`
2. `--subject` が既定値 `NA` のまま本番計測しないよう、`NA` の場合は起動時に警告を出す（止めはしない）
3. 実験条件は計測スクリプトに入力させず、**セッション台帳** `data/sessions_manifest.csv` を実験者が記入する方式にする（計測側の変更を最小にするため）。テンプレートを `docs/templates/sessions_manifest_template.csv` として作成
   - 列案：`session_base`（CSV名から拡張子を除いたもの）, `participant_id`, `group`（low/high）, `rank_current`, `rank_peak`, `map`, `agent`, `role`, `start_side`, `game_resolution`, `aspect`, `minimap_settings`, `eye_screen_distance_cm`（巻尺実測）, `calibration_file`, `video_path`, `notes`
4. 解析側（T4）で台帳を `session_base` で結合する

**受け入れ基準**：新列を含むCSVを旧版の解析スクリプト（ver2）と `gaze_visualizer_v3.py` がそのまま読める（列追加で壊れない）。研究室PCでの5分間テストで新列に値が入っている。

**注意**
- `gaze_data_callback` はTobiiのコールバックスレッドで動く。処理を重くしない（取得値をそのまま書くだけ）
- user coordinate system の原点はアイトラッカー中心。z は「眼−トラッカー距離」で「眼−画面中央距離」とは厳密には一致しない。卒論ではこの近似を明記する
- 変更後はユーザーに研究室PCでの確認手順（PowerShellコマンド付き）を示す

## T2 SDKによるキャリブレーション＋検証ツール（P0）

**なぜ**：Eye Tracker Manager のキャリブレーションは簡易的で、検証（どの位置でどれだけズレるか）の数値が残らない。予備実験で「上下端のHUDを見ても領域外に判定される」現象を観察している。現在ゼロ件の4つのAOI（round_timer, enemy_team_status, ammo_weapon, credits）はすべて画面端にあり、**「見ていない」のか「測れていない」のかを今のデータでは区別できない**。ゼロ件を結果として解釈するには、端の精度を数値で持っている必要がある。

**やること**
1. まず最小コードで、Tobii Pro Spark で `tobii_research.ScreenBasedCalibration` が使えるか確認する（使えない場合はこのタスクを「検証のみ」に縮小）
2. 新規スクリプト `src/gaze_estimation/calibrate_validate.py`
   - 対象ディスプレイを選択（既存の `select_display` を流用）し、pygame 全画面で 9点キャリブレーション
   - 続けて検証点を提示：9点に加え、**各HUD AOIの中心**（ミニマップ中心、上部バー、下部バー、右下クレジット付近）
   - 各点で注視開始後の安定区間（例：提示 800 ms 後から 500 ms）のサンプルで、accuracy（平均角度誤差、°）と precision（RMS sample-to-sample、°）を算出。角度換算には T1 の眼位置 z を使う
   - 結果を `data/raw/calib_<subject>_<YYYYMMDD_HHMMSS>.json` に保存（点ごとの値、全体平均、使用パラメータ）
   - 合否判定の閾値は引数で受け取り、既定値はユーザーと決める（案：全体平均 accuracy ≤ 1.0°、HUD検証点それぞれ ≤ 1.5°）
3. 実行タイミングは **VALORANT の試合を始める前**。試合中には起動しない

**受け入れ基準**：研究室PCで実行し、JSONに点ごとの accuracy / precision が出る。画面端の点の値から、各HUD AOIが測定可能な大きさかを T5 で判定できる。

## T3 分析区間（セグメント）の定義と注釈ツール（P0）

**なぜ**：分析区間（購入フェーズ終了 → 死亡/ラウンド終了）を、現在は動画を目視して Excel で行を削除した `_proc.csv` で作っている。この方法だと
- 行削除後に連続性を計算するため、ラウンドをまたいで注視・訪問・遷移が連結されうる
- 分析時間（分母）が区間ごとに追えない、作業が再現できない、11月の本格データ量（10名×2群×複数試合）では手作業が破綻する

**やること**
1. 区間定義ファイルの形式を決める：`data/annotations/<session_base>_segments.csv`
   - 列：`round`, `segment_type`（`alive` 固定で開始。将来 `buy` / `spectate` も可）, `video_start_sec`, `video_end_sec`, `end_reason`（`death` / `round_end`）, `side`（attack/defense）, `notes`
   - 時刻は **動画時刻** で持つ（目視で決めるのは動画上の時刻なので）。視線時刻への変換は解析時に sync の `offset_sec` で行う
2. 注釈補助ツール `src/visualizer/segment_annotator.py`（OpenCV による動画プレイヤー、オフライン専用）
   - 再生/停止、1フレーム送り・戻し、数秒スキップ
   - キー操作で「購入フェーズ終了」「死亡」「ラウンド終了」を記録、取り消し可能
   - 保存時に上記CSVを書き出す。ラウンドの攻守は手入力でよい
3. 既存の `_proc.csv` との整合確認：予備実験1試合分について、旧方式と新方式の有効サンプル数がほぼ一致することを確認する

**受け入れ基準**：1試合分（約13ラウンド）の区間付けを、動画を1回通して見る程度の時間で終えられる。出力CSVを T4 が読める。

**今はやらない**：ラウンドタイマーのOCRや死亡画面の自動検出による区間の自動化。手動注釈が安定してから、余力があれば半自動化（候補提示→人が確認）を検討する。

## T4 AOI解析の次版（P0・中核）

**なぜ**：ver2 の「注視」は AOI 内の連続サンプル区間（run）で、注視検出をしていない。
- 60 Hz の揺らぎで AOI 境界付近の run が細切れになり、`fixation_count` が水増しされ、平均注視時間が短く出る。視線が頻繁に通過するクロスヘアで特に強く効く
- 予備実験の「ミニマップよりクロスヘアの平均注視時間が短い」はこの近似の影響を受けている可能性が高く、I-DT で再計算するまで卒論の結果として扱わない
- 無効サンプルを除いた後に run を作るため、瞬目をまたいだ同一AOIが1回に連結される。`duration = samples × dt` も欠測を無視している
- ゼロ件AOIが出力から消える

**ファイル**：ローカルに ver3 があればそれを起点に `aoi_analysis-ver4.py`、無ければ `aoi_analysis-ver3.py`。ロジックは関数に分け、テスト（T7）から import できるようにする（ファイル名にハイフンがあると import できないので、ロジック本体は `src/aoi_detector/gaze_metrics.py` のような import 可能なモジュールに置き、バージョン付きファイルは CLI の入口にする）。

**入力**
- 視線CSV（必須）、AOI JSON（必須）
- 同期情報：`gaze_visualizer_v3.py` が保存する sync JSON、または `--offset`（区間ファイルを使う場合は必須）
- 区間ファイル（T3）：無ければ全区間を1セグメントとして扱い、警告を出す
- 解析パラメータJSON：画面の物理寸法（mm）・解像度、眼−画面距離（既定 650 mm。台帳/T1 の実測値で上書き可）、I-DT パラメータ、最大ギャップ等
- セッション台帳（任意）

**処理**
1. 有効性判定：`gaze_missing` が False、左右いずれかの validity が 1、座標が非NaN。画面外（0未満・1超）は **有効だが `offscreen`** として区別する
2. 区間付与：各サンプルに `segment_id` を付ける。区間外のサンプルは捨てずに `segment_id = NaN` として残し、以降の集計から外す（行削除しない）
3. 注視検出（I-DT）
   - 区間ごと、かつ欠測ギャップ（既定案 75 ms 超）で系列を分割し、その内部でだけ検出する
   - 分散 D = (max x − min x) + (max y − min y) を **視角（°）で** 計算：正規化座標 → mm（画面寸法）→ 角度（眼−画面距離）
   - 最短時間 100 ms、D ≤ 1.0° を開始値（パラメータで変更可）
   - 注視の時間は「最初のサンプル〜最後のサンプル＋1サンプル間隔」で、サンプル数×dt ではなく時刻差から求める
4. AOI割り当て：サンプル単位（Gaze % 用）と注視単位（注視の重心で判定）の両方。判定は numpy でベクトル化（`df.apply` をやめる）。重なりがある場合は JSON の記載順を優先し、その旨を出力に残す
5. サンプル分類：`aoi_fixation`（注視に属しAOI内）／`aoi_nonfixation`（AOI内だが注視でない）／`outside`／`offscreen`／`invalid`
6. 訪問：同一AOIに割り当てられた連続注視をまとめて1訪問。再訪数 = 訪問数 − 1（区間ごと）

**出力**（`data/processed/aoi_result/<session_base>/`）
- `samples_classified.csv`：時刻、座標、valid、segment_id、aoi（位置）、fixation_id、sample_class
- `fixations.csv`：fixation_id、segment_id、開始/終了、duration、重心、分散(°)、サンプル数、aoi
- `aoi_metrics_by_segment.csv`／`aoi_metrics_session.csv`：**全AOIの行を必ず出す（0件も）**
  - `gaze_pct`（分母＝区間内の有効サンプル。`offscreen` を分母に含めるかはパラメータ化し、出力に明記）
  - `fixation_count`、`fixations_per_min`（分母＝区間内の有効時間）、`mean_fixation_duration_sec`（0件なら NaN とし、件数列を併記）
  - `visit_count`、`revisit_count`
  - `ttff_sec`：各区間の開始から測る。その区間で一度も注視がない場合は NaN＋`ttff_censored=True`
- `transitions_long.csv`／`transitions_matrix.csv`：注視ベース、区間内のみ（区間をまたがない）
- `qc.json`：全体・区間ごとの有効率、分析時間、区間数、使用した sync offset と種類、眼−画面距離（中央値）、全パラメータ、スクリプト版、git コミット、入力ファイルのハッシュ

**受け入れ基準**
- T7 のテストがすべて通る
- 予備実験の1試合で、`gaze_pct` が旧版（同じ区間）とほぼ一致する（サンプルベースの定義は変えていないため）。一致しなければ原因を説明できること
- 全AOIの行が常に出る

**ユーザーに確認が必要な決定事項**（実装前に選択肢と推奨を提示すること）
1. 欠測ギャップの上限（注視を分割する閾値）
2. `offscreen` を Gaze % の分母に含めるか
3. 眼−画面距離を固定値（650 mm）にするか、セッションの実測中央値にするか（推奨：主解析は固定値、実測値は感度分析）
4. 時刻の基準：`pc_time_sec`（ホスト到着時刻）のばらつきを `system_time_stamp_us` と比較し、注視時間の計算にどちらを使うか。まず両者の差分の標準偏差を実データで出して判断材料にする（同期は `pc_time_sec` のまま）

## T5 AOI設定の物理パラメータ化と妥当性チェック（P1）

**なぜ**
- crosshair の半径 0.0351（=135 px）は「60 cm で半径2°」に相当し、実験条件の 65 cm では約1.85°。研究ノート上の計算（650 mm × tan 2°）とも一致しない。半径か直径かも明記されていない
- credits の高さは約65 px（65 cm で約0.9°）で、一般的な最小AOIサイズ（1〜1.5°）と Spark の精度を下回る。測れない大きさのAOIで「注視ゼロ」を報告すると誤った結論になる

**やること**
1. AOI JSON に物理条件を追加：`display`（幅mm・高さmm・解像度）、`viewing_distance_mm`。クロスヘアは `radius_deg` で定義し、正規化半径はスクリプトで計算する（手計算値を JSON に直書きしない）。既存の `radius_x/radius_y` 形式も読めるようにする
2. 検証スクリプト：各AOIの幅・高さを視角で一覧表示し、T2 の測定精度と比べて「精度＋最小マージンより小さいAOI」に警告を出す
3. OBS録画の1フレーム（`src/test/extract_frames.py` で抽出）にAOIを描画した画像を出力するオフラインのチェック機能。ライブのPyQtオーバーレイの代わりに、試合映像上でAOIの位置ずれ（特に画面端のAOI）を確認するため
4. 本実験で参加者のゲーム解像度が 3840×2160（16:9）以外、または4:3ストレッチの場合は、解析時に台帳の値を見てエラーにする

**受け入れ基準**：AOIごとの視角サイズ表と、実フレーム上のAOI描画画像が出る。クロスヘアAOIの定義が「半径 X°、距離 Y mm」として出力に残る。

## T6 セッション横断集計とQCレポート（P1）

**やること**
1. 全セッションの `aoi_metrics_session.csv` と台帳を結合し、整然データ（1行＝参加者×セッション×AOI×指標）のマスターCSVを作る
2. 参加者レベルの集計では **割合の平均ではなく、サンプル数・時間を合算してから割合を出す**（試合時間の違いで重みが歪まないように）
3. QCレポート（1セッション1行）：有効率、分析時間、sync が期待帯内か、眼−画面距離、キャリブレーション結果、解像度一致。除外基準に該当するセッションは **削除せずフラグを付ける**。除外基準の数値はユーザーと決める

**受け入れ基準**：予備実験の5試合から、マスターCSVとQCレポートが1コマンドで生成される。

## T7 解析ロジックのテスト（P1、T4と同時）

`tests/` に pytest で、合成データを使って次を確認する。
- AOI判定：矩形の境界（`<` と `<=` の扱い）、円（楕円）判定、重なり時の優先順位
- I-DT：既知の「注視→サッカード→注視」系列で注視の数・開始・終了が一致する。100 ms 未満は注視にならない
- 欠測ギャップと区間境界で注視・訪問・遷移が分割される
- 0件AOIの行が出る。`gaze_pct` の分母が有効サンプル数になっている
- TTFF の打ち切り（未注視区間）が NaN＋フラグになる

## T8 群間比較の統計スクリプト（P2）

**なぜ**：各群10名程度では検出力が低く、AOI × 指標の組み合わせが多いと多重比較で何かが偶然「有意」になる。

**やること**
1. 主要比較（例：ミニマップ Gaze %、クロスヘア Gaze %、HUD全体 Gaze %）を **設定ファイルで事前に宣言** し、それ以外は探索的として別表に出す
2. 群間比較：Mann–Whitney U、効果量（rank-biserial r または Cliff's delta）、ブートストラップ95%信頼区間。主要比較のファミリー内で Holm 補正
3. 個人値をすべて点で示す図（箱ひげ＋点）を出す。ゼロの多さや外れ値が見えるように
4. 探索的に、ラウンド単位データで参加者を変量効果とする混合モデル（statsmodels）を検討する

**注意**：検定の選び方・主要比較の選択は研究上の判断なので、実装前にユーザーと合意する。

## T9 配布形態（exe化）の検討（P2・保留）

研究室ミーティングで「他団体のPCにアプリを入れると嫌がられる → exe化」という案が出ている。ただし
- Spark を使うにはドライバー（Eye Tracker Manager 等）のインストールが必要で、exe化しても「何も入れない」は達成できない
- AOI はモニター（27型 4K）・解像度・HUD設定に依存するため、他団体のPCで計測するとAOIの前提が崩れる

したがって **参加者に研究室の計測環境へ来てもらう** 方針を推奨し、exe化はその方針が取れない場合にだけ着手する。着手する場合は PyInstaller で `tobii_research` のネイティブDLLを同梱できるかの検証から始める。

- 区間の完全自動化（OCR・画像認識）
- リアルタイムの視線フィードバック
- Tobii Webカメラ版との比較
